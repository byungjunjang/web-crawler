### 왜 이 실행이 처음 일어났는가 (추측 아님)

이 저장소는 fork 다(`gh api repos/joonake9644/web-crawler` → `fork: true`,
`parent: byungjunjang/web-crawler`). fork 는 Actions 가 **자동 활성화되지 않는다.**
그 상태에서 PR 을 열었을 때 `gh pr checks` 는 `no checks reported`,
`actions/runs` 의 `total_count` 는 `0` 이었다 — 워크플로는 `state: active` 인데
한 번도 실행된 적이 없었다.

해소: `PUT /repos/joonake9644/web-crawler/actions/permissions` 로 `enabled: true`
를 설정한 뒤 PR 을 close → reopen 해 `pull_request` 이벤트를 다시 발화시켰다.
그 다음 이벤트에서 첫 실행이 시작됐다. **즉 이전에 CI 가 없었던 것은 코드가
실패해서가 아니라 실행 자체가 시작되지 않았기 때문이다.**

이 실행을 gate 삼으려면 fork 에서 Actions 가 계속 켜져 있어야 한다. 꺼져 있으면
PR 에 check 가 뜨지 않고, 그 상태를 "통과"로 읽으면 안 된다.

## 상한 `<1.64` 재확인 — 2026-10-01 실측 (아직 유효)

ADR-002 가 "1.64 는 2026-09-28 시점에 없다"에 근거해 `<1.64` 를 넣었다.
시간이 지나 값이 달라졌을 수 있으므로 pypi.org JSON API 로 다시 잰다.

```text
playwright  1.6x 계열: ['1.60.0', '1.61.0', '1.62.0', '1.63.0']
patchright  1.6x 계열: ['1.60.0', '1.60.1', '1.61.1', '1.61.2',
                       '1.62.1', '1.62.2', '1.62.3', '1.63.0']
```

**1.64 는 여전히 미출시**다 — 두 패키지 모두 1.63.0 이 최신이라 `<1.64` 상한은
유효하다. 마이너 라인도 계속 나란히 움직인다(playwright 는 마이너당 1개,
patchright 는 추가 패치가 붙지만 마이너 라인은 동일). ADR-002 의 전제가
약화되지 않았다.

이 값은 시간이 지나면 저절로 낡아지는 값이라 **파일에 못 박는다**. 1.64 가
나오면 하한이 아니라 **상한을 함께** 올리는 갱신이 필요하고, 그때 이 절을 다시
