# 참고자료 — getdesign.ai 기능 대조 (2026-10-02)

**질문**: `https://getdesign.ai` 의 기능이 이 저장소(web-crawler)의 기능보다 우수한가?

**결론**: **비교 자체가 성립하지 않는다.** 두 도구는 목적·입력·출력·범위가 전부 다른
별개 범주다. 겹치는 지점은 "브라우저에서 DOM 을 읽는다" 하나뿐이다.
어느 한쪽이 다른 쪽보다 "우수"한 게 아니라 **푸는 문제가 다르다.**

> 이 문서는 사용자 지시("문서로 관련 내용 참고자료로 저장")에 따라 남긴 조사 기록이다.
> 가격·기능은 마케팅 페이지 문구를 2026-10-02 에 읽은 값이라 시간이 지나면 낡는다.

## 대상 정의 (혼동 주의)

| 이름 | 실체 | 이 문서에서 |
|------|------|-------------|
| **getdesign.ai** | Motionsites 가 만든 Chrome 확장. 렌더된 디자인의 요소를 복사해 AI 빌더에 붙여넣는 도구 | 이 문서가 다루는 대상 |
| `github.com/MohtashamMurshid/getdesign` | 동명의 **별개** 프로젝트. URL → `design.md` 스펙 생성 에이전트 | 무관 (동명이인) |
| `getdesign.io` | 또 다른 별개. 월정액 디자인 구독 서비스 | 무관 |

## getdesign.ai 실측 (2026-10-02, 마케팅 페이지·가격 페이지)

- 형태: **Google Chrome 전용 브라우저 확장** (fetch 시점 확장 스토어 외 채널 미확인)
- 한 줄 정의(사이트 원문): "A magical browser extension for vibe coding faster.
  Hover any element, copy it for Lovable, Claude, Cursor or Gemini."
- 입력: 페이지에서 **마우스로 요소(element) 하나를 hover**
- 출력: 그 요소의 HTML/CSS를 **AI 빌더에 붙여넣을 수 있는 형태**로 복사
  (대상 빌더로 Codex · Claude · Antigravity · Cursor · Lovable · Copilot 표기)
- 가격: 얼리액세스 세일 `$359 → $199`, **평생 라이선스 · 무제한 사용**(가격 페이지 표기)
- 범위(마케팅 문구 기준): 단일 요소 · 단일 페이지 스냅샷. 다중 페이지·API·데이터셋 언급 없음
- **UNVERIFIED**: 정확한 캡처 범위(computed style 포함 여부), 프레임워크별 출력 형식,
  페이지네이션/대량 처리 지원 여부는 마케팅 페이지 텍스트만으로 확인되지 않았다.

## 이 저장소(web-crawler) 실측 (README·`CLAUDE.md`·`SKILL.md` 기준)

- 형태: AI 코딩 에이전트가 따르는 **레포 + 스킬 + 규칙**
- 입력: **URL + 자연어 수집 항목** ("상품명·가격·평점 100개")
- 출력: **엑셀(`.xlsx`)** — 원시 JSON·진행상황·생성 스크립트 동봉
- 범위: 다중 페이지·페이지네이션·API 발견, 로그인/쿠키, 안티봇 사다리
  (WAF·Cloudflare·Akamai), 도메인 재사용 프로필, PII·법적 게이트, 소프트블록 검증
- 가격: 오픈소스 레포 (무료)

## 판정

- **이 저장소가 우위인 영역**: 브라우저로 페이지를 읽어 **대량 데이터를 구조화**하는 일.
  getdesign.ai 는 이 영역을 아예 다루지 않는다(단일 요소 스냅샷 전용).
- **getdesign.ai 가 우위인 영역**: 이 저장소에 **없는 기능 하나** —
  렌더된 디자인을 AI 빌더용 입력으로 내보내기. 그리고 셋업이 사실상 0인 확장 UX.
- **따라서 "우리보다 우수한가"의 답은 아니오**다. 더 정확히는
  **웹 데이터 수집 문제에서는 비교 대상이 아니고**, 디자인→코드 문제에서는
  이 저장소가 애초에 그 문제를 풀지 않는다.

## 이 기록이 남기는 것 (다음 계획에 쓸 수 있는 사실)

1. getdesign.ai 의 UX 강점은 **설치·조작이 가볍다**는 것 — 우리 도구의 알려진 약점
   (레포 셋업 필요)과 정확히 반대 지점이다.
2. 우리에게 없는 기능은 **"디자인/스크린샷 → AI 빌더 입력" 내보내기** 하나다.
   이 기능을 넣을지는 제품 우선순위 결정이며, 이 문서는 그 판단의 재료일 뿐 결정이 아니다.
3. 두 도구를 합쳐 쓰는 것도 가능하다 — 디자인은 getdesign.ai 로, 데이터는 이 저장소로.
